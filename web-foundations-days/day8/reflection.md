# Course Reflection

The most difficult concept in this course was understanding how to design a system that remains correct when many users perform the same action simultaneously. I initially found it challenging to understand why checking whether a seat is available is not enough to prevent double-booking. I overcame this by studying database transactions, conditional updates, and unique constraints. Applying these concepts to TicketHub helped me understand how the database can ensure that only one customer successfully reserves a particular seat, even when multiple requests arrive at the same time.

Based on the feedback I received on my capstone, I would improve the explanation of how the system handles failures and scales under heavy traffic. I would make the request flows more detailed and explain what happens when a database operation fails, a payment response is delayed, or a background job needs to be retried. I would also include more explicit assumptions behind capacity estimates and test the design against different traffic patterns. These improvements would make the design easier to evaluate and demonstrate how it would behave in real-world conditions.

Next, I want to learn more about cloud infrastructure and deployment, particularly how to deploy applications using Docker and a cloud platform. I also want to gain practical experience with load testing, monitoring, and distributed systems. Building and testing a small application with these tools would help me connect system design concepts to implementation and prepare me to design systems that are scalable, reliable, and secure.
